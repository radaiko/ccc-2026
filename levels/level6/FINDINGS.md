# Level 6 findings

- This is program synthesis and optimization: minimize the sum of instruction-line counts across all programs/files. Input headers add the required production count; output has no length headers, just six instructions per line and one empty line between programs.
- Level 5 simulation and automatic pickup still apply. Emitters reset to inactive at their original corners for every pattern, but do not reset between pickups within a program.
- Two nonparallel active emitters create exactly their intersection cell. Mapping target cells to their two emitter rail offsets turns safe simultaneous movements into a king-move graph. Covering this graph and reversing the walk gives a simple valid baseline, but multi-emitter programs score substantially better.
- Useful optimization: represent rays as bitsets of target and adjacent non-target cells. Exactly two hits create matter; three or more erase it. Restricting moves to never create adjacent non-target matter makes the target-only state exact, provided target destruction is also simulated. Distant waste is allowed by the rules.
- For six-emitter search, enumerate all simultaneous instructions with shared bitset prefixes. Prune a partial assignment if it creates adjacent non-target matter that none of the remaining possible rays can erase. This is much stronger than randomly sampling joint moves.
- Cache production transitions by emitter configuration: after each pickup the target is empty, so revisiting the same configuration permits reusing the same program segment.
- A static configuration that recreates the whole target produces one copy per waiting tick. Exact-two-hit cardinality constraints over six ray-choice domains find these configurations. Reject immediately when the sum of each emitter's maximum target coverage is less than twice the target size.
- A nearly complete beam-search state can be finished deterministically by switching to two nonparallel emitters and covering only the remaining target cells. This preserves useful partial results when the search times out.
- `candidates/astra.py` retains the accepted Level 5 simulator and includes a validity checker. `python3 levels/level6/candidates/astra_check.py astra_opt` runs the optimizing candidate, verifies every required count, and saves outputs under `runs/astra_opt/`.
- The stock runner's validator self-test assumes deleting the last sample instruction must invalidate an answer. That is false here: the official sample ends by switching off an emitter after its last pickup. Use semantic simulation, not exact sample-output comparison or that truncation assumption.
